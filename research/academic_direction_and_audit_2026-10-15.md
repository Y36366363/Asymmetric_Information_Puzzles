# AIP 学术定位、证据审查与发展路线（2026-10-15）

本文依据用户提出的 AAMAS workshop → 长期 AAMAS 正会目标制定。修订版 v2（2026-10-15）以 `c315efe` 为代码基线，纳入首次 M0 更新、远端 CI 失败诊断及自适应对抗器方向。旧版可由 Git 历史追溯。

它是未来发展规划，不是新实验预注册；具体模型调用、预算、统计方法和阈值须在各实验开始前另行冻结。本次修订同时记录 CI 判据修复，但不启动模型训练、不改变历史实验或运行时标签。各阶段按研究理解和证据推进，不因路线已经写下就自动执行全部阶段。

近期决策：CI 跨环境判据已修复；一骰私有信息泄露的最小语义实验也已完成。下一步先讨论并实现最小 GameSpec 观察字段切片，再以 Goofspiel 的同时秘密行动检验同一机制能否复用。自适应对抗器作为共享底座的第二研究线，在合法观察 schema 稳定后开展小规模模拟实验；首篇论文只选择一个主要问题。

## 1. 建议的中心定位

**面向有限不完全信息博弈的、可验证的 LLM 辅助建模与策略求解方法。**

长期“通解”应理解为统一问题表示、求解路由、验证与失败诊断流程。初期可认证范围限定为有限、两人、零和或已正确转换的常和、perfect-recall 游戏。多人一般和、未知对手模型、连续空间和不完整规则需单独声明解决概念与保证，不能直接继承 CFR 的均衡结论。

推荐方法链：自然语言规则 → 有类型的 GameSpec → adapter → 语义/信息集审计 → matrix/DP/sequence-form/CFR 求解 → 独立 BR/数值误差验证 → 带作用域证据的结果或明确拒绝。

LLM 的首要职责是识别玩家、观察、行动、chance、收益和缺失假设，以及基于验证反馈修复模型。精确数值计算交由适用求解器。CFR 是这一框架的重要后端，而不是所有游戏唯一入口。已有停止时间矩阵、Goofspiel DP 和 sequence-form 应继续保留。

项目总目标可扩展为：**对不完全信息博弈进行可验证建模、策略求解与受控对手适应。**其中 A 线研究“模型和解是否可信”，B 线研究“有限合法历史能否改善对抗表现，以及付出多少最坏情况风险”。两线共享游戏接口和独立评估器，但使用不同的研究假设、数据划分及成功标准。

## 3. 必须优先弥补的问题

### A. 语义正确性和结构正确性尚未连通

perfect recall、合法概率、action consistency 可以在一个“错误但自洽”的模型内全部通过。例如把对手私牌错误地公开，可能产生更细且仍满足 perfect recall 的信息集。需要从独立规则合同导出 observation invariance 测试：只改变不可见状态，不应改变行动者看到的信息或其 information-set key。同时覆盖 payoff 符号、chance 多重计数、同时行动泄露和停止条件错误。

语义合同与评分器不能完全由同一模型输出生成。以人工审查/程序生成的可信规则规范及隐藏测试作为外部依据；自生成测试通过只算自洽证据。

### B. “独立”需要写清是哪一层独立

当前 BR 不读取训练 regret 是重要隔离，但与求解器共用 adapter 并不等于独立规则实现。增加解析小例、手算反例、第二实现或 OpenSpiel 的匹配规则对照，检查模型层的共同错误。浮点 LP 的 exact-in-model 与数值容差也应明确，不能等同于形式化实数证明。

### C. 覆盖比例不等于均衡误差

对于已知有限博弈和完整策略，准确的全局 BR 可直接量化 exploitability；每个信息集都被训练访问并非 ε-Nash 的必要条件。旧覆盖门槛是额外的工程/研究验收，历史失败判定照旧保留。未来报告分开列出：规则语义、结构完整性、数值求解误差、策略完整性、观测覆盖和运行时政策。

`exploitability = NashConv/2` 与 `maximum_unilateral_deviation_gain` 要区分：若声称每个玩家的偏离收益都不超过 ε，应检查后者；只检查 NashConv/2 ≤ ε，通常只能推出每人偏离收益 ≤ 2ε。命名不能代替保证说明。

### D. 当前“通过”大多是工程验收，尚非统计性非劣结论

一个新 seed 上满足差值阈值不能证明总体非劣。相同 seed 重跑是复现，不是独立样本。多个剂量、连续多轮探索仍需计入研究历史；提前写 JSON 也不等于可由外部核验的预注册时间戳。下一轮采用 pilot/confirmation 严格划分、执行前 Git commit/tag 或外部时间戳、冻结主要终点和 seed 集合，报告所有结果和置信区间。

### E. 观测机制的理论与成本证据不足

原平均策略累计与 post-update 额外 observation pass 混合后的估计目标应写成公式；需分析信息集入样概率、策略时点和归一化。每 epoch 的 chance 边际精确，并不能单独证明对自适应策略序列的平均策略估计无偏。

下一比较应包含相同总资源下的更多标准 MCCFR 迭代、非分层额外 observation、分层 observation；只比较相同 regret iterations 会给新方法更多计算。墙钟需同时报告训练、观察、BR 和内存，固定硬件。覆盖提高不足以推出效率提升。

### F. 测试入口和跨环境判据已通过远端验证

首次审查发现 unittest 只收集 342 项，而 pytest 收集 523 项。`c315efe` 已将统一入口改为 pytest，增加七项证据索引测试、验证依赖版本和研究 CI。本地完整验证为 530 项 Python 测试、六条证据索引及 14 项浏览器测试通过，详见 [首次更新](academic_m0_first_update.md)。这不是重新执行全部历史实验。

[首次远端运行](https://github.com/Y36366363/Asymmetric_Information_Puzzles/actions/runs/38795050490/job/116629125532) 为 528 项通过、两项失败，后续证据与浏览器步骤未完成。诊断时本地对应两个测试文件共 11 项通过。Node 弃用提示不是该次失败的直接原因。

两个失败断言分别要求：新求解的一骰策略指纹与冻结策略完全相同；Guess Who 不同私人角色的首轮概率字典完全相等。它们可能混淆 artifact 身份、浮点差异、最优解非唯一性和对称性。尚未取得远端完整策略差异，不能把具体数值原因当作已证实。

修复已保存失败证据和环境信息。一骰测试现在分别核验冻结 artifact 自身的策略指纹、完整性和独立 BR；新解继续单独通过价值、流约束和独立 BR 门槛。Guess Who 测试保留“根节点不得盲猜”和“有歧义时存在正 reach 猜测”等战略性质，移除了任意 LP 最优解必须在不同私人角色根节点逐项完全相同的要求。规则对称保证对称均衡存在，并不保证求解器选择唯一的对称表示。修复没有刷新历史指纹、修改策略、删除独立认证或放宽 exploitability 阈值。

四种 `PYTHONHASHSEED` 下定向测试均为 11/11 通过；本地统一验证为 530 项 Python 测试、六条证据检查和 14 项浏览器测试通过。[修复后的远端运行](https://github.com/Y36366363/Asymmetric_Information_Puzzles/actions/runs/38950766924) 也完整通过，包括生成资产一致性检查。原 CI 阻塞至此关闭；旧失败运行继续保留为跨环境问题证据。

这项修复不需要回滚游戏。Pages 发布与研究 CI 当前仍独立，不能将研究 CI 误称为部署闸门。

## 4. 最小 workshop 论文

建议题目方向：**From Rules to Auditable Strategies: Verifying LLM-Assisted Imperfect-Information Game Models**。

核心问题：在固定资源下，基于语义合同与独立求解反馈的修复，是否提高新规则实例上的“正确建模且通过独立评估”的比例，并降低错误认证率？

冻结两类主要目标：一骰 stepwise Liar's Dice（隐藏类型、顺序挑战）与四牌 Goofspiel（同时隐藏承诺、公共库存）。Kuhn 为解析控制；E-Card 为 solver 退化/无差异控制；小 Love Letter 为 later-chance 编译验证，不强行当 belief-transfer 正控制。五骰与完整 Love Letter 为扩展研究，不让它们阻塞第一篇论文。

建议先定义一个受限声明式 GameSpec，避免一开始让 LLM 任意生成整套 Python。包括 players、chance law、observations、legal actions、transition、payoff、termination、solution scope、规则文本来源。参数化模板仍须支持真实的 payoff/chance/information 变化，而非只改游戏名字。

实验臂：

1. LLM 直接输出行动/策略（测决策效果，不要求它生成 adapter）。
2. LLM → GameSpec → solver，无验证反馈。
3. LLM → GameSpec → solver，仅语法与通用结构反馈。
4. 同样工具和修复预算，加语义/独立验证反馈（主方法）。
5. 人工正确 GameSpec → 相同 solver，作为求解上限与故障定位控制。

主要比较为 4 对 3，隔离语义验证的增量。模型固定，repair 次数、可访问规则、工具预算与总时间上限一致。把直接行动臂的决策指标单列，不能因它不输出 GameSpec 而判定建模失败。

主要终点建议为 held-out 实例上的端到端验证成功率：可信语义测试通过、策略合法且完整、独立 BR 达到预先声明误差、预算未超限。分母包括全部实例；超时、解析失败、拒绝均记录。并报告 false certification rate、覆盖—错误率曲线，防止“全部拒绝”获得虚假高可靠性。

次要指标：最终 oracle 上的 action regret/完整策略 exploitability、建模错误类型、修复次数、token/墙钟/内存成本、prior 与 policy-conditioned posterior 误差。有限次 LLM 动作抽样无法直接提供精确策略 exploitability；必须明确求得的完整行为策略还是有采样不确定性的估计。

验证集按结构/规则生成族划分，避免同一游戏仅换皮就称为 held-out transfer；可信 reference 与隐藏评测不给 agent。随机 payoff、chance 参数、行动重命名及单规则反事实变体用于检测记忆依赖，但不能单凭这些测试宣称排除训练污染。

先用 pilot 估计方差与失败率，再通过功效模拟冻结正式实例数、至少两个模型系列及每实例独立重复数。以基础规则实例/模板为 cluster 计算配对置信区间，重复调用不能冒充独立游戏。平局用 ε-optimal action set 评分。缺失对手策略时拒绝唯一 posterior 评分，或者显式提供 policy/reach 假设。

## 6. 正会升级的具体门槛

workshop 之后选择一个明确突破：具有语义保真约束的自动建模/修复方法，或有误差传播保证的求解与抽象流程，或多个真正 held-out 结构族上具有稳定收益的策略迁移。至少需更强基线、跨模型与规则族复现、足量独立样本、误认证分析与资源可扩展性证据。仅增加游戏数量、测试数量或再封装 CFR 不足以保证原创性。

若做理论，优先尝试受限 GameSpec 编译的观察/收益保持性质，以及在明确收益误差或策略近似假设下的证书组合；不要预先声称适用于任意 abstraction。LLM 应贡献可测的模型构建、路由或修复能力；人工正确模型交给经典 solver 的成绩必须单列。

## 7. 文献与投稿定位（本次核验）

- [OpenSpiel](https://arxiv.org/abs/1908.09453)：已有通用多游戏及算法基础设施；AIP 不能只以“统一平台”作为新颖性。
- [CFR 原论文](https://papers.nips.cc/paper_files/paper/2007/hash/08d98638c6fcd194a4b1e6992063e944-Abstract.html)：用其适用假设界定收敛保证；模拟/采样方法并不天然不科学或不准确。
- [Autoformalization of Game Descriptions using Large Language Models](https://arxiv.org/abs/2409.12300)：自然语言游戏形式化已有先例，需逐项比较语言范围、反馈类型和语义评估。
- [Steering Language Models with Game-Theoretic Solvers](https://arxiv.org/abs/2402.01704)：LLM 与博弈求解器结合已有研究，不能把工具组合本身当作首创。
- [GAMABench](https://arxiv.org/abs/2403.11807)、[GameBench](https://arxiv.org/abs/2406.06613)：多游戏 LLM 决策评测已存在；突出信息结构、独立证据及失败诊断。
- [AAMAS 2026 Strategic Explainability workshop](https://sites.google.com/view/se-aamas2026)：主题包含 LLM 将情境转成博弈模型，可作选 venue 的历史参考，不推定 2027 必定延续。
- [AAMAS 2027 main track](https://warwick.ac.uk/fac/sci/dcs/aamas2027/calls/call-for-main-track/)：常规论文截止 2026-10-08；以当前日期已过。GAAI/GTEP 的定位取决于方法贡献，而非标题关键词。

## 8. B 线：可验证的自适应对抗器与训练基准

### 研究目标与现有工作的边界

目标是依据规则允许的交互历史建立对手模型，在声明的最坏情况风险预算内提高收益，并向其他研究者提供可复现的对手池与适应评测协议。针对某个人变强不等于更接近 GTO；打不过一个对手也不能直接推出通用能力差。历史首先改善对手估计和响应策略，不自动改善 solver 的正确性或计算复杂度。

这一方向已有直接前例：[Restricted Nash Response](https://www.johanson.ca/publications/poker/2007-nips-rnash/2007-nips-rnash.html) 研究利用收益与鲁棒性权衡；[OX-Search](https://proceedings.mlr.press/v235/ge24b.html) 研究安全、鲁棒的子博弈利用；[PSRO](https://arxiv.org/abs/1711.00832) 以响应策略和策略种群组织多智能体学习。因此“记住玩家 + CFR/RL + 对手池”不是足够的新颖性主张。

AIP 待检验的差异化是：合法观测历史 → 可核查对手模型 → 响应候选 → 独立最坏情况评估 → 带条件的部署或回退。研究应输出具体失败诊断，例如信息泄露、观测不足、对手分布变化、模型误设和过度利用。只有比较最接近方法后证明额外价值，才能主张方法贡献；单纯接上现成组件可作为复现基线。

### 第一个可解释的小实验

先用已可精确评估的一骰规则及程序化模拟对手，不立即收集真人数据或训练深度 RL。观察预算按完整对局数冻结，先验、平滑、更新时机、随机种子和可见字段全部记录。对手隐藏骰子仅在规则允许揭示之后进入历史；模拟器内部真值仅供独立评分，不能进入 agent 输入。

建议比较：固定均衡参考；无历史固定启发式；基于简单频率/贝叶斯对手模型的直接响应；同模型的风险受约束响应。已知真实对手策略的响应仅作为 oracle 上限，不计入现实可用方法。先以小型精确计算实现响应，待复杂度成为实际瓶颈再引入 RL；LLM 可以后续用于提出行为模型或解释诊断，需与非 LLM 方法单独消融。

主问题：在相同交互预算下，方法能否在留出对手上提高相对固定均衡策略的期望收益，同时满足预注册的最坏情况损失约束？这里的“留出”指对手身份/参数/行为族与开发集分离；部署适应阶段允许访问约定数量的新对手历史。随后用冻结策略与独立新对局测收益，避免拿训练历史成绩当泛化证据。

对于零和博弈，令玩家 i 的博弈价值为 v_i，自身候选策略为 π_i。单边风险定义为
`risk_i = v_i - min_{σ_-i} u_i(π_i, σ_-i)`。
该量使用对手独立最佳回应计算；常和收益须先一致转换。它不能直接拿完整策略对的 NashConv/2 代替。部署门槛采用预先声明的风险上限和数值容差；风险检查不通过则回退到已验证参考策略。若只是冻结快照通过，报告只保证该快照，不声称整个跨局自适应过程已有安全定理。

完整状态机的在线适应会引入跨局记忆，原单局 perfect-recall/BR 认证不自动覆盖它。第一实验先评估“收集历史 → 冻结候选 → 独立评估”；后续另行定义在线过程的评测和保证范围。对手历史不是随机完整观测，隐藏信息/选择性揭示导致的偏差应显式建模。

主要收益终点及风险约束必须在 pilot 后、正式确认前冻结。按对手/种子进行配对设计，平衡玩家座位，以对手为适当聚类单位报告区间；对模型误设、未见行为族、行为切换和反制策略分别报告。不得按结果选择“最容易打败”的对手集合。若收益只发生在训练对手、风险越界或不优于简单模型，应保留零结果/负结果并缩小主张。

### 研究基准与游戏难度分开

| 模式 | 冻结内容 | 可以支持的结论 |
|---|---|---|
| 固定对手基准 | 策略文件、规则版本、seed 协议、角色和预算 | 对已公开或留出对手集合的可复现成绩 |
| 自适应基准 | 更新规则、记忆窗口、冷启动/重置、反馈时点和总预算 | 声明协议下的适应速度、收益及鲁棒性 |
| 玩家简单/困难模式 | 经测试的策略配置与难度定义 | 特定玩家群体/对手分布上的体验与性能，不代表通用排序 |

benchmark 至少包含均衡参考、多个不同弱点的对手、未见对手和反制压力测试，报告交叉对战矩阵。存在循环克制时不依赖单一 Elo 或一个胜率排名。训练对手池与最终评测池分离，避免对手持续更新导致不同研究者分数不可比。失败应定位到信息理解、预测、行动选择或适应预算，不能仅给出“AI 不够聪明”的判断。

未来真人历史采集另设数据方案：明确用户同意、最小字段、匿名标识、保留/删除机制和研究用途；按玩家分割开发与测试，避免同一人的历史泄露到两侧。行为偏好先限定为游戏中的行动倾向，不推断无关个人属性。涉及真人研究时在采集前核查适用的机构伦理要求。该部分尚未实施。

### B 线阶段门槛

1. B0：冻结合法历史 schema、模拟对手族和单边风险定义；由小型精确例子验证评分器。
2. B1：一骰 pilot 比较固定/直接响应/受约束响应，分开报告预测误差、收益、风险和成本。
3. B2：冻结算法与预算接口后横向接入 Goofspiel；新游戏需声明收益尺度及其风险预算，不机械复制原始分值阈值。
4. B3：只有 pilot 有可解释信号才预注册确认实验；必要时加入 RNR 等可实施基线，明确与现代方法的能力范围差别。
5. B4：发布版本化对手池和复现协议，再考虑 RL 扩展、真人适应和网页难度模式。

## 9. 原创性与首篇论文选择

近期默认仍为 A 线可验证建模。B 线是明确保留的第二目标，不强行塞入首篇论文。如果 A 线语义反馈缺少增益而 B 线小实验表现更扎实，可以在正式确认前记录研究方向调整；不能把探索中挑出的赢家直接包装成预注册发现。

每条贡献都应回答：与最接近工作比较新增了什么；去掉该组件是否退化；是否优于简单方法；失败在哪些游戏/对手上；同预算下是否仍成立。平台整合、更多游戏、更多测试和“使用 LLM”可以支持工程价值，不能单独证明方法创新。

A 线候选贡献为信息语义反例与修复反馈对未见规则建模的增量；B 线候选贡献为信息约束下可解释、可复核的对手适应及评测协议。两者当前均是研究假设。若最终只有可靠复现或系统性负结果，可据此定位 benchmark/position/workshop 论文，不虚构新算法优势。

## 10. 后续更新与研究者参与方式

执行顺序：一骰泄露语义小实验 → 解释结果并与研究者共同确定下一步 → A 线接口扩展或 B 线最小 pilot → 选择单一主问题进行预注册确认。暂不增加新 CFR 变体或更多游戏。既有五骰全预算预注册保持冻结且未执行，完整 Love Letter 继续未认证。

每次更新交付一份简明研究记录：本次问题、假设、改动、对照、实际测试/实验、结果与局限、涉及文件/commit，以及下一步选项。清楚标注“计划”“已实现”“本地通过”“远端通过”“独立认证”，避免把计划写成结果。

每次只推进一个可理解、可审阅的阶段。研究者应能用自己的话解释：为什么需要该实验、哪个结果会否定假设、当前证据没有证明什么。这是帮助理解的讨论，不作为机械测验。先讨论概念与结果，再决定下一轮研究投入；自动提交偏好不等于自动启动全部未来实验。

本修订记录了 CI 测试语义修复及本地、远端全量通过。GameSpec、泄露故障实验和自适应对抗器尚未开始。文献检索是定位起点，后续选定主问题后应建立可复查的相关工作比较表。
